# Decisions

- ADR-001: Three small crates, no third-party runtime dependencies. Keep engine portable; defer Android/UI/privileged code until transport contracts are designed.
- ADR-002: Strict one-datagram input, no trailing bytes. Conservatively reject IPv4 options/fragments and IPv6 extension headers; the original parser does not validate checksums or reassemble (optional checksum validation added by ADR-010).
- ADR-003: Lower numeric rule priority wins, then original input order. Return provenance and require explicit default action. O(R) scan avoids premature indexing.
- ADR-004: Directional flow observations, configured entry cap and monotonic u64 ticks. O(F) expiry is simple and testable; benchmark before optimizing. No TCP state-machine claim or implicit flow authorization.
- ADR-005: Stable Rust with tested MSRV 1.85; forbid unsafe. std-only implementation and committed lockfile reduce supply-chain exposure.
- ADR-006: Public standard Ubuntu Actions runners, independent bounded checks, SHA-pinned actions, read-only permissions. No Android SDK in milestone 1.

- ADR-007: Reject the entire policy on excess rules or inverted port ranges. `Policy::new` is now fallible; 4096 is a conservative engineering ceiling, not a measured latency guarantee. Smaller caller limits are supported; external file byte limits remain future work.
- ADR-008: Isolate fuzz-only dependencies and nightly from the stable/MSRV core workspace. Retain a fuzz lockfile and deterministic structural seeds. Use bounded address-sanitized CI smoke testing; core code continues to forbid unsafe. Exhaustive CIDR prefix/bit properties use independent mask oracles without adding a property-testing runtime dependency.

- ADR-009: Add a dependency-free release microbenchmark binary rather than nightly bench APIs or a framework dependency. Output raw per-sample CSV and preserve machine/toolchain context; exclude warmup from summaries. Include real expiry scans and allocation during insertion. No timing regression gate until variation is measured across repeated runs; no optimization is bundled with this baseline.

- ADR-010: Preserve metadata-only parse and add explicit parse_checked with checksum policy/result status. IPv4 UDP omission requires opt-in and is distinguishable from verified transport; IPv6 UDP zero-checksum tunnel exceptions remain unsupported. TCP zero checksums are validated normally. No automatic offload bypass; platform contract/device testing is required before strict TUN use. Independent Python big-integer fixtures and mutation tests validate the Rust folded-sum implementation.

- ADR-011: Implement an explicitly labelled drop-all diagnostic VPN before choosing a TCP/UDP transport. Java owns the TUN descriptor and its one reader; JNI handles bounded owned byte copies only. No raw FD crosses the bridge. Use a single symbol-export unsafe-lint exception in the adapter; core crates retain forbid. JVM smoke and ABI APK builds are required, while device tests remain separate. Disable always-on support and automatic restart for this diagnostic; no upstream sockets, no forwarding or implicit allow. The temporary Java Activity supplies platform consent/start/stop only, pending Rust-native UI evaluation.

- ADR-012: Replace per-packet HashMap retention with one BTreeSet last-seen record per flow. Preserve exact timeout/clock/capacity semantics, including u64 boundaries; validate against a linear reference. Changed timestamps cost O(log F), due expiry O(E log F), with extra bounded index memory and possible bulk-drain cost. Compile policy precedence once, retain original indices and validate against the previous min-priority oracle.
- ADR-013: Add a portable checked Engine with explicit admission/drop reasons and saturating aggregate counters. Policy changes are validate-before-replace and clear prior observations; responses require active original flow, exact reverse tuple and current directional allow. No authorization cache or TCP-state claim.
- ADR-014: Implement real, bounded nonblocking UDP relay before selecting a TCP stack. Require socket protection before connect, one socket per observed flow, explicit periodic expiry/reset, MTU rejection and no hidden queues. Reject unsupported alias/scope endpoints. Build checked reverse IP/UDP datagrams. Loopback-only tests open sockets; fuzz targets never perform network I/O. User requested APK/UI work remain paused.

- ADR-015: Add a std-only/internal-workspace DNS crate with a conservative one-IN-question profile, 4096-byte messages, bounded backward compression, 128 records and 32 EDNS options. Canonicalize an explicit ASCII label subset, reject unsupported input instead of ambiguous binary/Unicode matching. Exact/subdomain rules use explicit priority and original-index provenance.
- ADR-016: Enable question-only DNS filtering explicitly on selected UDP destination ports. Retain one pending ID/question per flow; accept identical retransmission, reject conflicting concurrency rather than grow an unbounded query map. Require current domain plus inbound packet allow and exact transaction/question association before delivering a response. Updates/reset/expiry revoke pending state. No alias-chain, DNSSEC, encrypted/TCP DNS or global domain-access claims.

- ADR-017: Select pinned smoltcp 0.12.0, 0BSD/MSRV 1.80, with minimum raw-IP IPv4/IPv6/TCP/std features to preserve tested Rust 1.85. Versions 0.13/0.14 require 1.91; revisit this tradeoff with future advisories/MSRV upgrades. Use socket2 0.6.5 to protect an unconnected upstream stream before connect and OS entropy via getrandom 0.2.17 for each virtual interface.
- ADR-018: One virtual interface/socket and OS stream per flow, hard cap 64, explicit <=16 MiB payload budget, one RX slot and bounded TX slots. Accept the SYN in the stack before creating an upstream socket. Partial writes consume only accepted prefixes; half-close directions remain independent. Preserve TIME-WAIT, reap accepted RST/listener rollback, authorize output against current reverse policy, and best-effort reset forced upstream teardown. Reject time values before i64-microsecond overflow. No TCP DNS/Android integration claim.
- ADR-019: Add cargo-deny advisory/license/source policy for runtime and isolated fuzz graphs, plus ARM64/x86_64 transport compile checks. Use deterministic no-OS-socket TCP stack fuzzing and actual loopback I/O tests as separate evidence, not interchangeable proofs.
- ADR-020: Add pinned rustix 1.1.6 (default features off; `std`, `event`) on Unix for a safe `poll(2)` readiness wait instead of writing an unsafe FFI boundary, keeping `netscope-transport` under `unsafe_code = forbid`. Accepted after cargo-deny (advisories/licenses/sources), Rust 1.85 tests and Android-target checks passed; its internals remain a trusted dependency. The wait is `poll(2)`, not epoll, so cost is linear in waited flows; revisit with measurements.
